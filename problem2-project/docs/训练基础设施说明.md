# 问题 2 训练基础设施

这批实现连接了 Dataset、音视频标准化、词元缺失增强、固定验证场景和训练预测流程。文本编码器仍可替换；验证模型仅使用随机初始化的词元嵌入，不依赖外部文本模型或情感数据。

本轮已完成：15 项测试通过；全量训练集统计与验证场景库已生成；65 条训练样本跑完两轮（每轮含最后一个单样本 batch），33 条验证样本完成固定缺失情景预测，30 条 aligned 专项样本完成无标签推理。模型保存加载预测一致，另有合成数据测试证明恢复训练与连续训练参数完全一致。运行报告位于 `outputs/infrastructure/run_report.json`，版本记录位于同目录 `environment.json`。

## 运行方式

CPU 版 PyTorch 安装在项目 `.venv` 中，虚拟环境复用现有 Python 的 NumPy 等包，不修改全局 Python 的包。它不是完全封闭的可移植环境，运行报告记录实际版本。

```powershell
Set-Location 'problem2-project'
.\.venv\Scripts\python.exe -m unittest -v test_p2.py test_aligned_dataset.py test_pipeline.py
.\.venv\Scripts\python.exe run_infrastructure.py
```

重建环境时先用 `python -m venv --system-site-packages .venv`，再执行：

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.14.0+cpu --index-url https://download.pytorch.org/whl/cpu
```

## 标准化

MaskedStandardizer 只接受声明为官方训练划分的 Dataset。使用增量均值与方差统计 audio/vision 的原始可用位置，不计算文本编号的均值和标准差。没有可用行的模态会报错；常数维度的缩放因子设为 1。统计量保存到 JSON，验证与专项推理只能读取或复用。

转换仅作用于原始掩码标为可用的位置，其余位置保持零。判断可用性不依赖标准化后的数值。重复调用同一对象 fit 会报错，防止推理流程意外重新拟合。

本次小规模模型训练使用 65 条样本，但标准化器使用官方训练集全部 3395 条。这不使用验证信息；结果不能解释为仅使用 65 条样本完成的完整统计学习实验。

## 文本缺失增强

增强作用在编码前的 input_ids 上：将选中区间的编号、attention 和 segment 值置零，并更新文本可用与池化掩码。原始 extent_mask 不变，其他模态不会被文本遮蔽连带截断。音视频增强同时清零对应特征并更新各自掩码。

当前采用“删除可观测输入”的候选策略，不假定词元编号 100 或其他特定词元就是专项数据中的缺失标记。若后续确认专项文本缺失使用另一种机制，应增设策略并在相同协议下比较。

模型只在可用位置取输入；文本编号在嵌入查表之前应用掩码，音视频也在投影前应用掩码。接入上下文文本编码器后，仍需保证相同的输入屏蔽和输出池化原则。

## 固定场景库

覆盖全部 728 条验证样本。提供 3 个种子、7 个模态组合、3 个比例（10%、30%、50%）、4 个位置（首/中/尾/随机），另加完整输入，共 253 个情景、184184 条样本级记录。

记录包含样本 ID、原始掩码指纹、种子、区间、名义比例和实际比例，不使用标签。相同位置/种子下的区间随比例嵌套；在保持至少一个原先可用位置、避开不允许遮蔽的位置等约束下，允许实际比例低于目标。各模态区间独立，不声称它们在真实秒数上同步。

首部、中部、尾部为确定性位置，因此这三类情景在不同种子下可能完全相同；不能当作三个独立随机重复估计不确定性。随机位置情景才体现种子变化。所有模型从同一文件读取遮蔽计划，应用时核对 ID 与掩码指纹。

## 训练循环与恢复

训练实现分类交叉熵与回归均方误差的可配置加权和、非有限损失/梯度检查、梯度范数裁剪、保留最后不足一批的样本、模型及 Adam 状态保存。每个 epoch 的采样顺序由 seed+epoch 决定。

恢复校验模型配置与标准化文件哈希，恢复模型、优化器和 CPU Torch RNG。本轮保证 CPU、epoch 边界的恢复；不支持中途 batch 恢复，也未验证 GPU 随机状态恢复。

预测函数只向模型传入明确列出的输入字段，不访问目标标签。无标签 Dataset 没有伪造的中性标签。专项预测文件名含 SMOKE_ONLY_NOT_SUBMISSION，样本编号仍为追踪键，不是正式提交文件。

## 边界

随机词元嵌入是验证工具，不是确定后的文本编码器；固定词表容量 32768 仅是覆盖当前输入编号的工程上限，并不认定 tokenizer 身份。超出编号范围应明确扩展或采用确定的未知词策略，不能静默取模。

这轮不进行大规模调参或模型优劣选择，不评价官方 test。原始样本和标签不修改。`.venv`、完整实验日志与原始数据不应直接放入竞赛提交包。
